# Decision Principles

1. Prefer the smallest credible public product, not the smallest possible mockup.
2. Prefer architecture before code for multi-file and risky work.
3. Prefer explicit domain rules over premature generic frameworks.
4. Prefer synthetic data and sandbox integrations until a real pilot exists.
5. Prefer one operator-neutral adapter boundary over early support for many operators.
6. Prefer measurable commercial learning over feature volume.
7. Prefer reversible decisions before deployment.
8. Do not allow technical polish to replace product launch.
9. Do not claim facts, compliance, integrations or results that are not verified.
10. Update documentation only when it improves the next stage.
